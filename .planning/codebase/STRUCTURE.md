## Directory Purposes

**`HeftyBack/cmd/server/`:**
- Purpose: Entry point for the backend application
- Contains: Single `main.go` file that wires all dependencies
- Key file: `main.go` → loads config, creates repos, creates handlers, registers services, starts server

**`HeftyBack/internal/handlers/`:**
- Purpose: RPC service implementations, business logic execution
- Contains: 7 handler files (one per service) with ~70+ methods total
- Pattern: Each handler struct has 1+ methods, each method validates input, calls repo, handles errors
- Key files:
  - `auth.go` - Login endpoint
  - `session.go` - StartSession, SyncSession, FinishSession
  - `errors.go` - handleDBError() function for error mapping

**`HeftyBack/internal/repository/`:**
- Purpose: Data access layer, abstract all SQL queries
- Contains: Interface definitions + 7 implementations (one per service)
- Key files:
  - `interfaces.go` - All repository interface definitions
  - `session.go` - Most complex repo (handles sessions, exercises, sets)
  - `workout.go` - Workout template CRUD with sections/sets

**`HeftyBack/internal/middleware/`:**
- Purpose: Cross-cutting concerns for all requests
- Contains: Auth interceptor (JWT validation), logging interceptor
- Key file: `auth.go` - Validates Bearer token, extracts user ID, adds to context

**`HeftyBack/internal/auth/`:**
- Purpose: JWT token generation and validation
- Contains: JWT manager with token generation, claims validation
- Key files:
  - `jwt.go` - GenerateToken(), ValidateToken()
  - `context.go` - ContextWithUserID(), UserIDFromContext()

**`HeftyBack/proto/heft/v1/`:**
- Purpose: Protocol Buffer service and message definitions
- Contains: 7 .proto files (one per service + common.proto)
- Pattern: Service definitions match RPC method signatures, messages match request/response types

**`HeftyBack/migrations/`:**
- Purpose: Database schema version control
- Contains: SQL migration files in order (00001, 00002, etc.)
- Pattern: Each migration has +goose Up/Down sections for forward/rollback

**`HeftyBack/tests/integration/`:**
- Purpose: End-to-end tests against real database
- Contains: 7 test files (one per service)
- Pattern: Each test uses pgtestdb for isolated DB, TestServer for all service clients

**`hefty_chest/lib/core/`:**
- Purpose: Infrastructure and configuration
- Contains: RPC client setup, logging, session storage
- Key files:
  - `client.dart` - Creates transport, defines service clients, auth interceptor
  - `config.dart` - App configuration (backend URL, etc.)
  - `logging.dart` - Pre-defined loggers (logAuth, logSession, logWorkout, etc.)
  - `http.dart`, `http_io.dart`, `http_web.dart` - Platform-specific HTTP clients

**`hefty_chest/lib/features/`:**
- Purpose: Feature modules, each self-contained with providers and widgets
- Pattern: Each feature has `{feature}_screen.dart`, `providers/`, `widgets/` subdirectories
- 9 features: auth, home, calendar, progress, profile, tracker, workout_builder, program_builder, history

**`hefty_chest/lib/features/tracker/`:**
- Purpose: Live workout session tracking
- Special: Uses Freezed models for immutable session state
- Key files:
  - `tracker_screen.dart` - Main UI
  - `models/session_models.dart` - SessionModel, SessionExerciseModel, SessionSetModel
  - `providers/session_providers.dart` - Session CRUD, sync operations

**`hefty_chest/lib/shared/`:**
- Purpose: Reusable components across features
- Contains: Theme configuration, common widgets (buttons, dialogs, pickers)
- Key files:
  - `theme/app_colors.dart` - Color palette constants
  - `theme/heft_theme.dart` - FTheme configuration
  - `widgets/floating_session_widget.dart` - Persistent session overlay

## Key File Locations

**Entry Points:**
- Backend: `HeftyBack/cmd/server/main.go` - Starts HTTP/2 server, wires dependencies
- Frontend: `hefty_chest/lib/main.dart` → `lib/app/app.dart` - Initializes app

**Configuration:**
- Backend: `HeftyBack/internal/config/config.go` - Loads .env variables
- Frontend: `hefty_chest/lib/core/config.dart` - Hardcoded backend URL, rest timer duration

**API Definitions:**
- Backend: `HeftyBack/proto/heft/v1/` - 7 .proto files (auth, user, exercise, workout, program, session, progress)
- Frontend: `hefty_chest/proto/` - Same 7 .proto files (must stay in sync)

**Core Logic:**
- Backend handlers: `HeftyBack/internal/handlers/{service}.go` (7 files)
- Backend repositories: `HeftyBack/internal/repository/{service}.go` (7 files)
- Frontend providers: `hefty_chest/lib/features/{feature}/providers/{feature}_providers.dart` (9 files)

**Testing:**
- Backend unit tests: `HeftyBack/internal/handlers/{service}_test.go` (7 files)
- Backend integration tests: `HeftyBack/tests/integration/{service}_test.go` (7 files)
- Frontend integration tests: `hefty_chest/test/integration/providers/{service}_provider_test.dart` (7 files)
- Frontend E2E tests: `hefty_chest/test/integration/e2e/{flow}_test.dart` (2 files)

## Naming Conventions

**Files:**
- Handler files: `{lowercase_service}.go` (e.g., `session.go`, `workout.go`)
- Repository files: `{lowercase_service}.go` (e.g., `user.go`, `exercise.go`)
- Test files: `{filename}_test.go` (Go convention)
- Provider files: `{feature}_providers.dart` (e.g., `workout_builder_providers.dart`)
- Screen files: `{feature}_screen.dart` (e.g., `tracker_screen.dart`)
- Widget files: `{descriptive_name}.dart` (e.g., `exercise_card.dart`, `set_row.dart`)
- Proto files: `{lowercase_service}.proto` (e.g., `session.proto`)

**Directories:**
- Feature directories: `{feature_name}/` (snake_case, plural if multiple items: `handlers`, `repositories`)
- Subdirectories within features: `providers/`, `widgets/`, `models/` (standard structure)
- Internal packages: `internal/{package}/` (all lowercase, e.g., `internal/handlers`)

**Code Symbols (Go):**
- Types: PascalCase (e.g., `UserHandler`, `SessionRepository`)
- Functions: PascalCase for exported, camelCase for private (e.g., `GetProfile`, `handleDBError`)
- Variables: camelCase (e.g., `userID`, `sessionID`)
- Constants: SCREAMING_SNAKE_CASE or PascalCase (e.g., `DefaultRestTimer` or `PORT`)

**Code Symbols (Dart):**
- Classes: PascalCase (e.g., `SessionModel`, `WorkoutBuilder`)
- Functions: camelCase (e.g., `getProfileProvider`, `startSession`)
- Variables: camelCase (e.g., `workoutId`, `isLoading`)
- Constants: lowerCamelCase (e.g., `defaultPageSize`)
- Providers: `{name}Provider` (e.g., `workoutListProvider`, `sessionSyncProvider`)

## Where to Add New Code

**New Backend Endpoint:**

1. **Proto Definition** (`HeftyBack/proto/heft/v1/{service}.proto`):
   - Add RPC method to service
   - Define request/response messages
   - Example:
   ```protobuf
   service MyService {
       rpc DoSomething(DoSomethingRequest) returns (DoSomethingResponse);
   }
   ```

2. **Repository Method** (`HeftyBack/internal/repository/interfaces.go` + implementation):
   - Add method signature to interface
   - Implement in `HeftyBack/internal/repository/{service}.go`

3. **Handler Method** (`HeftyBack/internal/handlers/{service}.go`):
   - Implement method matching RPC signature
   - Extract userID from context
   - Call repo method
   - Map domain model to proto response

4. **Tests**:
   - Unit test: `HeftyBack/internal/handlers/{service}_test.go`
   - Integration test: `HeftyBack/tests/integration/{service}_test.go`

5. **Code Generation**:
   - Run `make generate` to generate proto code

6. **Database** (if needed):
   - Create migration: `make migrate-create name=descriptive_name`
   - Add SQL in migration file
   - Run `make migrate-up`

**New Frontend Feature Screen:**

1. **Create Directory**: `hefty_chest/lib/features/{feature_name}/`

2. **Screen Widget** (`{feature_name}/{feature_name}_screen.dart`):
   ```dart
   class MyFeatureScreen extends ConsumerWidget {
     const MyFeatureScreen({super.key});

     @override
     Widget build(BuildContext context, WidgetRef ref) {
       return Scaffold(
         body: // ...
       );
     }
   }
   ```

3. **Providers** (`{feature_name}/providers/{feature_name}_providers.dart`):
   ```dart
   @riverpod
   Future<MyData> myData(Ref ref) async {
     // Fetch from API
   }
   ```

4. **Widgets** (`{feature_name}/widgets/{widget_name}.dart`):
   - Feature-specific UI components

5. **Route** (`lib/app/router.dart`):
   - Add TypedGoRoute definition
   - Add route class

6. **Code Generation**:
   - Run `flutter pub run build_runner build --delete-conflicting-outputs`

**Shared/Reusable Component:**
- Location: `hefty_chest/lib/shared/widgets/{component_name}.dart`
- Use in multiple feature screens via `import 'package:hefty_chest/shared/widgets/{component_name}.dart'`

**Utility/Helper:**
- Go backend: `HeftyBack/internal/{package}/{utility}.go`
- Flutter: `hefty_chest/lib/core/{utility}.dart` or feature-specific `lib/features/{feature}/utils.dart`

## Special Directories

**`HeftyBack/gen/`:**
- Purpose: Generated code (never edit manually)
- Generated by: `buf generate` command
- Committed: Yes (to version control)
- Contains: Protobuf message types (.pb.go files) and Connect-RPC service handlers (.connect.go files)

**`hefty_chest/lib/gen/`:**
- Purpose: Generated proto code (never edit manually)
- Generated by: `buf generate` command
- Committed: Yes (to version control)
- Contains: Protobuf message types (.pb.dart), enums (.pbenum.dart), RPC clients (.connect.client.dart)

**`HeftyBack/bin/`:**
- Purpose: Compiled binary output
- Generated by: `make build` or `go build`
- Committed: No (added to .gitignore)

**`hefty_chest/test/integration/`:**
- Purpose: Integration tests requiring backend
- Execution: Requires Docker (PostgreSQL container) + backend running in TEST_MODE
- Command: `./scripts/run_integration_tests.sh`

**`.env` file (not checked in):**
- Purpose: Environment variables (DATABASE_URL, JWT_SECRET, etc.)
- Location: `HeftyBack/.env`
- Pattern: Copy from `.env.example`, fill in values
- Never committed due to containing secrets
